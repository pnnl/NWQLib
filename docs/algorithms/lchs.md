# LCHS for linear dynamics

`LCHS` selects a finite approximation to `du/dt = -A u + b`. Supply the original matrix, physical initial vector, time and optional constant source in `LinearDynamics`; the Method owns its numerical choices. The default output is the physical solution in the original coordinate order.

```python
from nwqlib import LinearDynamics, solve
from nwqlib.algorithms import LCHS

problem = LinearDynamics(A=[[.4, .15], [.05, .25]],
                         initial_state=[1, 0], time=.1)
result = solve(problem, method=LCHS())
print(result.solution)
```

This default builds one nine-qubit dense SELECT with 204 physical branches and 256 address slots. The branch matrices are computed classically from each node's Hermitian eigensystem and inserted into controlled circuits. This is a finite native implementation. `execution="classical"` evaluates the selected finite numerical model and reports classical outputs. Larger problems need a supported structured construction with its own limit check.

For a constant source, this small classical selection fits the default limits:

```python
source_problem = LinearDynamics(A=[[.6, .1], [.1, .3]],
    initial_state=[1., 0.], time=.1, source=[.2, -.1])
source_result = solve(source_problem, method=LCHS(), execution="classical")
print(source_result.solution)
```

It evaluates a finite LCHS/Duhamel sum. Its observed absolute L2 discrepancy is about .00110499 on this example. Default quantum selection instead needs 1836 physical branches, 2048 padded SELECT slots and 12 total qubits, exceeding `max_dense_select_slots=256`, so it rejects before native construction. The reconstruction fields `coefficient_l1_norm`, `physical_branches` and `padded_branches` describe the coefficient table of a `Plan`, the selected construction and its costs, computed before any circuit exists. They therefore differ between the classical and quantum `Plan` objects of this Problem. The classical `Plan` evaluates the initial state and each of the eight Duhamel nodes with the same 204 kernel coefficients, and it reports their dimensionless one-norm 1.40368 and 204 branches. A quantum `Plan` prepares all 1836 branches in one SELECT, each kernel coefficient multiplied by the initial-state norm or by a Duhamel weight times the source norm, so its one-norm, 1.43507 once `max_dense_select_slots` accepts the `Plan`, is in the solution's unit. `duhamel_nodes` selects time-quadrature accuracy and cost, while `max_dense_select_slots` limits materialization. Neither is automatically changed to fit. Each dense branch is a controlled, classically computed matrix exponential, so the slot cap bounds construction cost and memory, while fewer Duhamel or k nodes would change the selected approximation. The refusal names the time, tolerance, limit or backend choices that the caller can change. General time-dependent A or source is not implemented. See the [technical roadmap](../ROADMAP.md).

For a classical Pauli product formula, planning stores the selected coefficient table once per k node and the elapsed time, step count and route per application. Rotations are derived at application time with the selected coefficient-times-elapsed-divided-by-steps order. The limit check follows the maximum of decomposition, node-table construction and action phases, while every selected payload still live remains charged. Vector actions use `cos(a)*v - i*sin(a)*P@v`. A large repetition count can instead select one dense step and binary powering. With dimension D, r effective repetitions and R rotations per step, the routing proxies are `r*R*(W_action + 2*D)`, where `W_action` is the single-label Pauli action law of `operators._pauli.pauli_action_requirements`, and `R*D**2 + (floor(log2(r))+popcount(r)-1)*D**3 + D**2`. The vector update adds one D-entry scaling and one D-entry scaled addition per rotation, with scalar trigonometric preparation bundled into those kernel/pass units. Effective repetitions are `max(1, steps)` for the saved step count. Only routes whose known arrays and work fit the Method limits are eligible, and equal work selects vectors. These are operation size proxies, not timing predictions. The node table, per-node steps, routes and route work are stored in the selected `LCHSData.host_actions` of the `Plan`. Construction work and aggregate action work are in `plan.reconstruction.classical_work`. `result.applications` holds one record per operator application with its schedule and component facts. The host kernel declares the records' JSON size bound, so the Run sets aside their bytes with the outputs. Reading a report or archive does not reselect or execute an action. Constant-source nodes use their own elapsed time and PSD recovery. The `dense_exact` backend instead forms one Hermitian eigensystem per node and uses it for every operator application, the nonzero initial state and each constant-source node, each at its own elapsed time.

## Selection and accuracy

The default kernel is `near_optimal_eq7` with `beta=.75`, composite Gauss quadrature, `truncation_multiplier=1`, and `approximation_tolerance=.01`. Beta lies in ACL's practical range in [Sec. 2.2](https://arxiv.org/html/2312.03916v2#S2.SS2). The construction allocates half the tolerance to the cutoff tail and half to k quadrature. It chooses K by inverting the finite tail bound from ACL Eq. (186), independently of panel width. An explicit multiplier at least one can enlarge this cutoff. Small nonzero dissipation remains a quadrature problem, while exactly zero L uses the unitary identity.

For this automatic provider pair, Q-point Gauss panels are selected using the Bernstein-ellipse bound of [Trefethen, ATAP Theorem 19.3](https://www.chebfun.org/ATAP/chap19.m) (ISBN 978-1-61197-239-9), Eq. (19.8), whose index is `n=Q-1`. ACL's own panel prescription (arXiv:2312.03916v2, Lemma 11, Eqs. (64)-(65)) assumes `T*max||L|| >= 32/e`. The first example (`A=[[.4, .15], [.05, .25]]`, `time=.1`) has `T*||L|| = .045`, so that premise fails there, while the ellipse bound holds for every `T*||L|| >= 0`. With strip margin d=.1, b=.9, h=K/m and `log(rho)=asinh(2*b/h)`, the bound is `64*K*exp(b*T*||L||)/(15*C_beta*d*(rho**2-1)*rho**(2*(Q-1)))`. The finite scalar search chooses the fewest nodes satisfying this quadrature bound and builds only the selected grid. The composite-Gauss provider first completes its scalar panel search. It stops when the minimum node count of every later panel count exceeds the best rule found. It then checks `max_quadrature_work` against the search charge, 32 units per selected node and the cubic Gauss-rule construction charge, before allocating the node arrays. A refusal names the complete charge of that selected rule. The limit therefore admits the search charge plus the selected rule's construction, not every scalar probe. The stored h1 is that grid's actual panel width; non-Gauss rules have no such panel width. The closed tail bound is `2*exp(-x)/(beta*C_beta*x)`, with `x=cos(beta*pi/2)*K**beta`, from ACL Eq. (186) and `E1(x)<=exp(-x)/x`. Eq. (62) may tighten it only for K>=1. Bounds are binary64 evaluations, not interval arithmetic; positive underflow is rounded upward, never labeled exact zero.

The tail step follows by substituting x=c*K**beta in the integral of the pointwise ACL bound (arXiv:2312.03916v2). It gives `2*E1(x)/(beta*C_beta)`, then `E1(x)<=exp(-x)/x` gives the closed expression. For the complex-strip quadrature bound, the Hermitian part of `-i*T*(k*L+H)` is `T*Im(k)*L`, so the logarithmic-norm bound handles noncommuting L and H. Applying the scalar ATAP inequality to v*F(k)u for arbitrary unit vectors and taking their supremum gives the same operator-norm bound without a dimension factor.

For the matrix above, K is about `27.51574`, the tail bound is `.005`, and the quadrature bound is about `.00431140`. With this unit input and no PSD shift, the physical facts `kernel_approximation` and `k_quadrature` of the `Plan` equal these unit-input bounds. The observed physical absolute L2 discrepancy is about `.000821472`. Changing the construction tolerance to `.001` selects 396 branches, with tail and quadrature bounds about `.0005` and `.000450744`. Its classical finite sum has discrepancy about `.0000532605`. A dense quantum realization of that finer choice would need 512 address slots and ten total qubits, exceeding the default 256-slot cap. The two component budgets do not prove a bound on total physical-output error, which also depends on input scaling, PSD recovery, preparation, evolution and numerical errors.

The finite tail budget increases node counts relative to the asymptotic cutoff recipe. Representative scalar selections at T*||L|| equal to .045, 5, 10, 50 and 100 use 204, 276, 344, 900 and 1590 nodes, compared with 72, 100, 128, 348 and 622 under that recipe. These are node counts, not runtime ratios. Controlled evolution also depends on operator width, the selected backend and the larger cutoff. The unchanged work, byte and SELECT-slot limits can reject a construction that previously fitted.

The published stage `kernel_approximation` and reconstruction field `kernel_approximation_bound` refer to the error in replacing the exact propagator by the selected finite kernel integral. For the ACL Eq.(7) kernel (arXiv:2312.03916v2) this is the cutoff tail. For Low–Somma it also includes the R-independent approximate-identity term in [Theorem 1, Eq. (8)](https://arxiv.org/html/2508.19238v2). Increasing the cutoff alone does not remove that second contribution. The two names state that error in two frames. The reconstruction fields `kernel_approximation_bound` and `quadrature_bound` bound its operator norm for a unit input vector, before the PSD growth factor, and the Result summary labels them "per unit input before PSD growth". The facts `kernel_approximation` and `k_quadrature` in `plan.facts`, which a classical Result also carries in `result.facts`, are physical L2 bounds. They multiply the field by the input norm, the Duhamel weight and `exp(psd_shift*t)` of each operator application and sum over the applications, so for `initial_state=[20, 0]` with the matrix above the facts are twenty times the fields.

These component bounds describe the finite sum in exact arithmetic. The terms of that sum have norms that add up to alpha times the input norm, where alpha is the coefficient 1-norm, while the exact solution of the shifted problem is no larger than the input norm. A large alpha therefore means cancellation, and binary64 evaluation carries rounding of order `u*alpha` times the input norm, with u = 2**-53. Because the LCHS error model reports floating-point error as unknown, planning refuses a coefficient table whose `u*alpha` exceeds 0.1 times `approximation_tolerance`, the error budget of each realization stage. This affects Low–Somma with a large shift c, whose alpha is close to `exp(c)*erfc(1/(2*gamma))`, with gamma the kernel width that the same [Theorem 2](https://arxiv.org/html/2508.19238v2) selects, about 1.2e16 at c = 50.

Known negative spectral endpoints of L follow `make_l_psd`. The default shifts L and restores the physical growth factor, while `make_l_psd=False` rejects a violation beyond the numerical PSD window. The window is `psd_tolerance*||L||_2`, the scale of the eigensolver's rounding (LAPACK Users' Guide, 3rd ed., Sec. 4.7), so the decision does not depend on the time unit. There is no Method option to bypass a known false premise. The lower-level `cartesian_decomposition(..., eigcheck=False)` remains a decomposition-only operation. It does not establish PSD or replace the Method's check.

Error components fall into two classes. Discretization error (the kernel-integral error, k-quadrature and, with a source, Duhamel quadrature) separates the exact propagator from the finite sum. Realization error (product-formula or QSP synthesis and approximate state preparation) separates that finite sum from the realized block. Each stage becomes a physical-vector bound by its own rule. The kernel-integral, k-quadrature and product-formula stages are weighted per application by the input norm, the Duhamel weight and `exp(shift*elapsed)`. QSP synthesis and coefficient preparation are scaled by the recovery scale of the prepared coefficient state. The Duhamel and input-preparation stages are already physical bounds. The available stages are summed once and then converted to the requested output frame, and each component is reported with its own value or reason.

Planning fixes the inputs of the kernel-integral, k-quadrature and budgeted product-formula bounds, so `plan(...).facts` already holds their values. A classical `Plan` lists these stages, and its Result records the same values as sums over the executed applications. A quantum `Plan` also lists the preparation stages and, for QSP, the QSP synthesis stage. For a dense A, the synthesis stage of fixed-step `trotter` and the Duhamel stage of a nonzero constant source stay unknown on both routes until `LCHSRefinement` evaluates them. The one exception is quantum `qsp_block_encoding` with A = 0, whose constant Duhamel integrand gives an exactly zero Duhamel stage.

The selected `Plan` keeps its actual nodes, coefficients, PSD conversion, input directions and numerical products. `plan(...)` does not obtain a solution or run a reference comparison. `estimate(plan)` folds the actual selected Program without native construction. Numerical errors whose bounds are unavailable remain unknown.

The ordinary `compare` entry selects several configured LCHS Methods for one Problem and estimates their resources before execution. Kernels compared on identical signed-binary nodes isolate the kernel change. Low–Somma selects its own symmetric trapezoidal grid from its tolerance, so a comparison that includes it changes the kernel–quadrature pair. Comparisons at fixed construction settings do not measure cost at matched accuracy. The MPS analysis below studies compression and circuit fitting for one kernel–quadrature pair.

## Native methods and physical coordinates

Select these alternatives with `LCHS(hamiltonian_evolution_backend=...)`. `trotter_steps` controls fixed repetitions, and on the compact periodic route `trotter_synthesis_tolerance` can select them instead (see the periodic paragraph below). `trotter_order` selects the Lie-1 or Suzuki-2 formula of either product-formula backend. `dense_exact` and `qsp_block_encoding` apply no product formula and accept only the default order 2. `psd_tolerance` is the numerical PSD check window. Kernel and k-grid choices use `lchs_kernel` and `k_quadrature`. The [LCHS API](../api/algorithms/lchs.md) explains the MPS/PREP controls and work/byte caps. Those limits do not prove a bound on the total physical error.

`dense_exact` and `qsp_block_encoding` do not use `trotter_steps`. The Method canonicalizes that field to one before constructing its identity, so Methods that differ only in an ignored supplied step count have the same identity. Planning emits a `UserWarning` when a nondefault supplied count was ignored. The private record of that supplied value is not reconstructed by `model_copy()` or by loading the canonical Method.

When revising to `hamiltonian_evolution_backend="trotter"`, set `trotter_steps` in the same revision. Revising only the backend uses the canonical one step. `trotter_error_budgeted` chooses per-branch counts from its separate error budget based on `approximation_tolerance` and requires `trotter_steps=1`.

- `dense_exact` computes each selected small branch matrix from its node's Hermitian eigensystem and controls the corresponding circuit definition. `dense_control_route` selects how the address bits control a branch on two or more system qubits. The default `"auto"` synthesizes the whole controlled branch for one address bit and controls each synthesized gate for more ([selected blocks](../blocks.md#dense-control-route)). On the gate-wise route, before adding the address controls, `qiskit_compat.controlled` replaces the dense branch unitary by a circuit of CX and one-qubit gates that equals it to rounding (`subroutines/_dense_synthesis.py`). Generic control would otherwise use Qiskit 2.5.2's own synthesis, which replaces a two-qubit unitary close to the identity by a local gate. A branch `exp(-it(kL+H))` is close to the identity when `t(kL+H)` is small, for example after a short elapsed time, and for such a branch that replacement would give entry errors measured up to 4.2e-5 ([dependency issues](../dependency_issues.md)). The [selected blocks guide](../blocks.md#controlled-dense-unitaries) describes the construction. The CX law of this backend, `dense_branch_select_cx` in `native.py`, bounds on the gate-wise route the gate census of that synthesis and prices each gate at Qiskit's count with the address controls added, and on the whole-matrix route it is the CX bound of the whole-matrix synthesis on the system qubits and the address bits. Planning charges the classical work and bytes of each node eigensystem and branch matrix (`time_independent_terms._spectral_branch_requirements`, as [Engineering constants](../ENGINEERING_CONSTANTS.md#numerical-choices-and-representation-sizes) registers it), of each branch synthesis and of Qiskit's control of the synthesized gates with the address bits to `max_select_work` and `max_bytes` ([selected blocks](../blocks.md#admission-of-the-exact-synthesis)). These charges depend on the system dimension, the node and branch counts and the address width, not on the norm of the branch generator. For the test problems of `_dense_select_problem` in `tests/test_lchs_resource_structural_law.py`, the largest power-of-two branch counts that the default `max_select_work` accepts are 8 on 5 system qubits, 4 on 6, 32 on 4 and 128 on 3, and it refuses 16 branches on 5 system qubits (1.01e8 units) and 8 on 6 (2.16e8 units). A dense-dilation child of `qsp_block_encoding` is charged the same way, and `dense_control_route` also selects how the joint generator's combine qubit controls it. With one address bit the whole-matrix route charges the whole-matrix synthesis on the system qubits plus one instead, and the boundaries above hold under the default `"auto"`.
- `trotter` uses fixed-step sorted-Pauli Lie-1 or Suzuki-2 evolution. Its actual order and per-node repetitions are saved.
- `trotter_error_budgeted` gives each node the smallest step count r for which r one-step bounds at step length `t/r`, plus the published pruning bound `t*m` for an upper bound m on the pruned Pauli mass, fit the per-node error budget of 0.1 times `approximation_tolerance`, with t the node's elapsed time (CSTWZ doi:10.1103/PhysRevX.11.011020, Sec. V B). It does not read `trotter_steps`, so a Method that pairs it with a value other than the default 1 is refused. The one-step bound is CSTWZ Proposition 9, Eq. (120), for `trotter_order=1` and Proposition 10, Eq. (121), for order 2, with each commutator norm replaced by its triangle-inequality sum over Pauli terms. Each one-step bound is a constant times the square (order 1) or cube (order 2) of the step length, so order-1 step counts grow as the inverse of the per-node error budget and order-2 counts as its inverse square root. The budget bounds only the product-formula synthesis error of each node.
- `qsp_block_encoding` selects the actual L/H block encodings, joint-generator diagonal weights, polynomial and phases once. Execution and archive loading reuse those products. Its synthesis ancillas join the actual success projector. An exactly zero joint generator has identity evolution with no invented zero scale or phase fit.

Dense product-formula planning decomposes L and H once with the recursive Pauli block transform. Its work and output conversion grow as q*d² for d = 2^q. Under the string-table work law and the default `max_select_work=100_000_000`, the decomposition sets aside 87,570,944 units at d = 512 and 385,888,256 at d = 1024. The decomposition stage therefore accepts at most nine system qubits. At nine qubits, decomposition plus the conservative second-order relaxed SELECT coefficient-selection law accepts 236 nonidentity union labels for 200 distinct nodes and 256 padded slots, or 235 labels for 4096 padded slots. These figures assume no identity coefficient, p entries in each L/H support, and the full pair envelope. They include support alignment and the dropped-mass work set aside. Angle-table work, the byte check and native construction remain separate limits on a complete `Plan`.

The spectral check uses the physical dimension before padding. For nonzero L, its default `max_spectral_work=100_000_000` accepts physical dimension at most 464, so a power-of-two physical input reaches 256 coordinates. Dimensions from 257 to 464 pad to 512 coordinates. An exactly zero L skips the spectral solve. Classical product-formula selection also charges coefficient preparation and the selected vector or dense-power actions. Its limits depend on the node and term counts as well as the matrix dimension.

`LCHS(max_admission_steps=1_000_000)` bounds the kept field slots of each Program that LCHS builds and the admission work of one check of that Program. A larger Program is refused with the field name, the refused stage and its count. For the kept field slots that count is complete, and raising the field to it passes the slot count. For admission work it is the count reached when the check stopped, a lower bound. In both cases later admission, preparation and lowering can need more. The field changes the metadata-work allowance, not the selected quantum operations.

The dense exact route reuses one Hermitian eigensystem for each distinct kL+H across source elapsed times. Host evaluation applies its phases to vectors without forming each dense propagator. A native SELECT that needs explicit branch matrices still forms and synthesizes those matrices under its work and byte limits. PSD recovery uses each application's elapsed time. “Dense exact” identifies the ideal matrix function, while its binary64 evaluation and circuit synthesis carry numerical error. Dense SELECT reuses the selected Hermitian eigensystem at each generator node and forms one elapsed-time branch matrix at a time. Its storage law includes the live factors, matrix-formation workspace, synthesis/control workspace and completed branch circuits. Host vector actions and explicit native branch matrices have different operation counts. The selected construction's resource record prices the operations it actually performs. The dense exact route evaluates the selected Hermitian matrix function in binary64. Host evaluation applies it to vectors using shared eigensystems, while native SELECT construction forms the required branch matrices. Eigensolver, phase-evaluation, contraction and circuit-synthesis errors remain separate from the real-arithmetic LCHS approximation budget.

Product-formula selection shares the ordered Pauli-label structure across k-nodes and evaluates each node's bound coefficient once. Initial and source applications reuse that coefficient at their own elapsed times, pruning charges and selected step counts. The full Pauli-triangle census is used when its remaining work and storage fit. Otherwise selection uses the second-order suffix relaxation and records `bound_variant="relaxed_prefix"`. The remaining work always includes node-specific magnitude evaluation and the route's other work.

For order two, consider 200 distinct active k-nodes, nine active applications and one shared sorted union of p nonidentity labels, with no identity coefficient. Use p entries in each L/H dictionary, p kept terms at every node, and the full pair/triple population envelopes. The preparation and census work laws, including support alignment and the dropped-mass work set aside, reach the following largest p under `100000000` units of planning work. The fixed-step bound computation obtains each distinct node's stored coefficients with one visit per kept label/coefficient pair and two scalar visits for the identity coefficient and upper dropped mass. Their work also includes the census consumer's preparation charge, the shared census and application arithmetic. At 20 system qubits, the full/relaxed pairs are 111/557 for proven fixed-step bounds, 114/693 for the host stage and 113/687 for SELECT coefficient selection. At nine qubits the pairs are 112/630, 114/693 and 114/693. The SELECT figures use 4096 padded slots. These are work-only stage ceilings, before decomposition, host actions, SELECT angle tables and native construction. The actual limit check also includes the live payload and census storage, so these figures do not imply that a complete dense `Plan` fits. In particular, the current dense arrays at 20 qubits exceed the default byte limit. A homogeneous 200-node SELECT uses 256 padded slots, while the field-padded layout with an initial state and eight source applications uses 4096. Padding adds slot records and angle storage but no new k-node census. The census population laws are `census_work` and `census_bytes` in `subroutines/trotterization/error_budget.py`, and `_lchs_census_choice` in `time_independent_terms.py` applies them to the shared structure and distinct node contractions, adding 9 bytes per row of the larger of the pair and reserved triple populations for one node's row selection ([Engineering constants](../ENGINEERING_CONSTANTS.md#other-numerical-guards)). Each caller adds its own preparation and application charges.

The product-formula bound computation checks its pair and triple structures against the limits before construction. A shared ordered support pays the mask tests once, while every distinct active node pays its own magnitude contraction. The byte check includes combined-node records and other allocations that remain live during that phase. Initial and source applications reuse the node coefficient at their own elapsed times, pruning bounds and selected or saved step counts. Padded slots do not create additional node censuses. The full second-order expression is used when its complete remaining work and storage fit. Otherwise the accepted suffix relaxation supplies an upper coefficient, or selection stops before the refused stage.

The dropped coefficient mass is an upper bound for the terms actually omitted. Its product with the evolution time is published upward as the pruning bound. The product formula is selected against the requested error budget minus that published pruning bound, rounded downward. Its formula bound and the combined pruning-plus-formula bound are published upward. These directions ensure that the exact sum of the published contributions and the published total do not exceed the requested error budget. Selection can require additional steps or fail when no positive representable formula error budget remains.

`lcu_select_implementation="auto"` uses only eligible existing implementations and their selected cost rules. Explicit `structured`, `multiplexor` and `branch_controlled` choices keep their own domains. `structured` requires proof of an eligible affine structure, computed from the selected k-node addresses and the actual generator's real Pauli coefficients.

For non-power-of-two matrices, the encoded problem is `A ⊕ 0`, with zero-padded initial and source vectors. PSD shifting includes the dummy coordinates coherently. Original spectral facts and the analytic zero endpoint determine the padded frame; a second padded eigensolve is unnecessary. Results project back to the original coordinates. Constant sources keep their actual Duhamel times, weights, physical input norms and elapsed-time PSD compensation.

`Solution` and physical `StateVector` preserve the physical phase and norm. Unit `StateVector`, `NormSquared`, `QuadraticForm`, `NormalizedExpectation`, and `Samples` each consume their own actual readout. Counts do not recover a complex vector. Samples exclude dummy coordinates; normalized outputs are unavailable when valid physical mass is zero.

With `shots=None`, a scalar observable is evaluated from one simulation of the selected coherent circuit. The readout fixes the method's success and physical-condition bits and excludes dummy coordinates. A Pauli observable with L terms then needs O(LN) classical work on the N-coordinate encoded system. The normalized expectation divides the projected quadratic moment by the physical-slice mass. A physical quadratic form also applies the method's recovery scale. Exact readout has no finite-shot error, while circuit, observable-action and normalization rounding remain separate error contributions. Normalized outputs are unavailable at zero physical mass.

Exact readout reduces the saved state to scaled scalar statistics. The reduction scans the complete native norm and success mass in bounded tiles, shares the physical mass when the populations coincide, and evaluates the observable on the success-and-physical slice. The limit check includes the saved state, the observable's serialized, parsed and packed representations, and the workspace for gathering, scaling and grouped action. Scaled statistics carry the recovery information needed for reanalysis. At readout and publication, LCHS resolves the amplitude-derived masses label of the producing preparation record, because the projected kernel bounds its own scaled squared-norm reductions. It uses the resulting qualified saved-state budget (`saved_state_error`, the native-state budget propagated through the envelope of the host phase correction of the saved state) when available and the preparation record's probability-check tolerance convention, propagated through the same correction, otherwise. A preparation record whose host phase correction was not assessed supplies neither, and the mass check refuses the point. Both branches include the host mass error budget, preserve the raw masses and check their nested populations. The `probability_window_exclusions` of the preparation record, in `result.data.receipts`, shows which branch applies. The budget applies when `amplitude-derived masses` is its only label. Any other label, such as `unitary` or `multiplexer` for a supplied matrix instruction, `optimization_level` for a non-default compiler level or `unchecked qiskit-aer version`, keeps the probability-check tolerance convention, and so does a preparation record whose exclusions were not assessed. `max_select_work` funds SELECT construction. `max_readout_work`, whose default is 2,000,000,000, funds sampled-readout grouping comparisons and exact projected-reduction input visits. The reduction's known live payload and workspace must also fit `max_bytes` before the native circuit runs.

Sampled observable readout groups qubit-wise-commuting Pauli terms into shared local bases. `shots` is the number of shots per selected group. Terms in a group share outcomes, so uncertainty calculations use the weighted group outcome and its covariance. Grouping reduces the number of settings. Its variance at fixed total shots depends on the state, coefficients and allocation. A padded normalized output also measures its physical-coordinate mass in an unrotated basis. Every counts setting measures all success and system qubits into one shared classical layout, and a group decodes each label's parity from the coordinates of that label's support. The grouping comparisons are charged to `max_readout_work`. The Result records each group's labels, basis, returned and selected shots and weighted moments. `Samples` stores its original-coordinate indices and counts as two integer arrays. Sampled group decoding and `Samples` read outcomes of at most 64 measured bits.

Classical observable outputs use one storage-preserving action, with binary scaling combined with the vector's physical recovery before producing the scalar. A representable quadratic form can therefore remain available when its normalized moment or physical norm squared is not. If a common observable scale would erase a nonzero entry, the original unscaled action is selected before execution; no second action or implicit dense conversion is performed. Binary64 cancellation and heterogeneous-range limitations remain, and an unrepresentable result is unavailable rather than a clipped value. Work and workspace include the observable copy and scans.

The PSD recovery `exp(shift*T)` can exceed binary64 while the physical solution does not, for example when strong growth acts on a tiny input. The coefficients and arrays then hold each recovery divided by `2**e`, with `e = floor(shift*T/ln 2)`, and `2**e` joins the binary output scale, so a representable solution is still returned. The weighted error components need the recovery as a number and are unknown with the reason `unrepresentable_psd_recovery:applications`.

Time equal to `initial_time` removes evolution. Known input vectors and norms are direct identities. A requested quantum observable or sample still uses its actual PREP and readout. An explicit classical vector observable is obtained once on the host and recorded. Analysis and archive loading reuse its stored scalar. A compact zero state never reaches PREP: normalized outputs are undefined, and a requested physical zero array has one bounded, recorded materialization.

Form the Cartesian parts L=(A+A†)/2 and H=(A−A†)/(2i) from one conjugate-transpose workspace. The parts are private arrays and become read-only after the PSD decision and any diagonal shift. Non-power-of-two input is padded as A⊕0, with the known zero eigenvalue added to the original spectral endpoints. Sequential padding and in-place scaling bound the declared array storage by four encoded complex matrices plus the vector workspace explicitly set aside. Coefficient-only selection computes the unpadded Hermitian endpoints with the planner's spectral owner and adds padding zeros analytically. Its limit check counts the known NumPy arrays and excludes the linked eigensolver's queried workspace. PSD compensation remains part of the selected coefficients.

An exactly zero Cartesian L has known spectral endpoints `(0,0)`: its eigensolve and the associated cubic-work limit check are omitted. Near-zero nonzero L still follows the selected spectral and PSD rules.

## Explicit checks and saved results

```python
from nwqlib.algorithms.lchs import LCHSVerification
from nwqlib.evidence import Certificate

checks = LCHSVerification(reference="expm", metric="absolute_l2", threshold=.01)
receipt, facts = result.verify(checks=checks)  # The only reference computation.
print(facts[0].fact.value.value)  # This comparison emits a Float64 discrepancy.
certificate = Certificate(plan_id=result.plan_id, result_id=result.content_id,
    assessment=result.assess(absolute_tolerance=.01), checks=())
certificate = certificate.with_verification(result, options=checks, evidence=facts)
print(certificate.checks[0].status)  # PASS: the .000821... discrepancy is below .01.
result.save("lchs-result")
```

Checks are explicit extra computations. `expm` compares homogeneous physical evolution. Source references include `ivp`, `closed_form`, or `ivp_closed_form` with their stated domains and controls. `closed_form` evaluates both terms of ACL arXiv:2312.03916v2, Eq. (2), with one exponential of the augmented matrix `[[-A*T, b*T], [0, 0]]`, whose top-right block is the Duhamel term `(integral_0^T exp(-A*s) ds) b`. It equals `A^{-1}(I - exp(-A*T))b` for invertible A, is defined for singular A as well and avoids the cancellation of forming `I - exp(-A*T)` when `||A||*T` is small. The `expm` and `closed_form` references use `scipy.linalg.expm`, or `scipy.sparse.linalg.expm` for a triangular matrix, because SciPy's dense kernel loses accuracy on triangular input with close diagonal entries ([Dependency issues](../dependency_issues.md#triangular-matrix-exponential)). A reference whose matrix has a 1-norm above `2**37`, or whose exponential is not finite in binary64, is reported as unknown. `selected_grid` compares the obtained result to its exact saved finite recipe, including actual PF steps, rather than an ideal exponential substituted for a PF gate. The classical selected-grid reference reads the selected coefficient table at most once per distinct k-node with a nonzero coefficient. Fixed-step refinement reads every distinct k-node of the table once. A borrowed selected row costs one logical visit, and reading the identity coefficient and upper dropped mass costs two visits per node. The table remains in the consuming phase's held payload. Census preparation, application phases and bounds, vector actions and requested dense validation have separate charges. Fixed-step refinement evaluates the saved step counts using the saved coefficients and pruning mass. The selected-grid quantum reference evolves the application vector through the selected decomposed branch circuit. Its work follows each executed gate's contraction arity and its workspace includes state rearrangement copies. `LCHSRefinement` requests component-bound analysis with its own explicit limits. Its verification record contains all observations, while the second returned tuple contains only output-error facts suitable for assessment, so a spectral-norm-only request leaves that tuple empty. Reference discrepancies are empirical numerical evidence, not a complete proven error bound.

`load_result(...)` preserves the original Method, `Plan`, obtained output, saved phases, MPS cores and numerical data. The saved selection names a separate JSON file with NPY arrays for the native data that grows with the grid and schedule: node and coefficient tables, host actions and SELECT angle tables. Loading binds each block payload as planning did. SELECT takes that data and the Problem's elapsed time, the periodic leaves take the periodic Strang payload, the input preparation is the Problem's initial state, and a PREP block takes its saved tensor. Loading recomputes `selected_identity` for `LCHSData` and compares it with the SELECT block or host kernel, and it recomputes the `preparation_identity` of each saved PREP payload. The periodic Strang payload is used as saved. Loading does not fit phases, solve an eigensystem, recompute a reference or reselect a grid.

`receipt` and `facts` record the computation, and the CheckAssessment above applies its threshold using the same facts and Result context, without calling `verify` again. These facts answer only `checks`. Another threshold, metric or reference needs `result.verify(checks=...)` with the new options, which computes the reference again ([Verification](../verification.md#facts-belong-to-the-options-that-produced-them)). The aggregate accuracy assessment can independently remain INCONCLUSIVE. See [error evidence](../error_evidence.md).

## Coefficient MPS analysis

```python
from nwqlib.algorithms.lchs import resolve_lchs_coefficient_plan

coefficients = resolve_lchs_coefficient_plan(problem)
decomposition = coefficients.decompose_mps(max_bond_dim=4)
```

The PREP target is the ordered normalized magnitude tensor `sqrt(abs(c) / sum(abs(c)))`. Complex coefficient phases remain in SELECT. An existing `Plan` exposes its actual coefficient selection. Overrides require a new `Plan`. Positive scaling permits reuse of identical normalized tensor data, while reordering or changing the tensor rejects stale cores. TT compression error and layered MPS circuit fidelity are different quantities. Another kernel–quadrature pair has its own coefficient tensor and needs its own decomposition. Constant-source quantum construction supports direct PREP only. MPS PREP there would need its own decomposition of the source-branch coefficient tensor and of both input directions.

Finite-layer MPS PREP may change the realized LCU block even when TT-SVD discarded weight is zero. Its circuit error remains unevaluated until an explicit validation of that selected circuit; the report states this scope.

The report reads stored MPS layer count, maximum stored bond, core bytes and selected construction work. Native circuit fidelity validation still performs an explicit statevector simulation, and explicit MPS reference analysis may reconstruct the tensor. Neither is called by reporting. `max_svd_work` bounds the prospective TT-SVD and the layered circuit construction, whose law `mps.layered_construction_size` follows the scikit_tt sweeps that `mps_circuit.mps_to_circuit` repeats after every extracted gate. The direct MPS builder checks both before it starts. LCHS planning checks the layered construction of each `mps_circuit` PREP against the Method's `max_svd_work` and `max_bytes`, the limits its lowering applies again. Opaque dependency workspace remains unknown.

## Resource inspection

`estimate(selected_plan)` reads selected laws. For a separate native representative calculation:

```python
from nwqlib.algorithms.lchs.quantum_resources import sample_resources

samples = sample_resources(result.plan, max_qubits=13)
```

`samples["representatives"]` lists each representative circuit with its name, its multiplicity in the selected construction and its operation inventory. `samples["weighted_totals"]` gives, for each readout setting (a sampled group, a mass setting or the exact reduction), the operation counts of every core representative multiplied by its multiplicity, plus the counts of that setting's readout representative. A representative's operation names stand for every block it represents, so a weighted count under a node-specific name can cover several nodes. Weighted totals are estimates. They do not model angle-specific cancellation, cross-block optimization or SDK workspace, and they do not combine depths. A dense exact SELECT builds no representative. Its `samples["structural_bounds"]` record uses the value-independent upper counts of the selected library synthesis and control route for every physical branch. Each record identifies its basis, route, owner assumptions and `count_kind="structural_upper_bound"`. It is not an observed circuit inventory, and the weighted totals do not include it. Counts for an arbitrary explicitly requested compilation continue to require its actual circuit inspection. Source and compact periodic workloads use explicit full inspection of `prepare(plan).inspect_resources(index=...)`. Shared `inspect_circuit_resources` does no simulation and transpiles only when requested. No resource calculation establishes solution accuracy.

Import the inspection owner as `from nwqlib.backends.inspection import inspect_circuit_resources`. A logical fold can instead select `ResourceContext(basis="cx")`, as shown in [resources](../resources.md), without preparing a circuit.

The linear dynamics notebook (`examples/lchs_linear_dynamics_intro.ipynb`) applies LCHS to advection-diffusion. It separates product-formula error from quadrature error and compares kernels, quadratures, and exact and MPS state preparation by their errors, success probabilities and gate counts. The LCHS scientific notebook (`examples/lchs_scientific.ipynb`) applies a constant source and imaginary boundary penalty to four-coordinate heat flow. Running its cells performs one ten-qubit quantum solve, within a 12-qubit cap, and separates LCHS approximation error from finite-penalty error. Its canonical source is `examples/generators/lchs_scientific.py`.

Periodic planning preserves compact inputs. The native Strang path keeps the one-qubit double-wrap edge convention. Its synthesis bound for r symmetric Strang steps is B/r², per unit input, with B = T³ Σ_j |c_j| (2|k_j| diffusion + |potential|)³ / 3 over the selected nodes k_j and coefficients c_j (`periodic.select_periodic_parameters`). `trotter_steps` fixes r. `LCHS(hamiltonian_evolution_backend="trotter", trotter_steps=None, trotter_synthesis_tolerance=eps)` instead selects the smallest r with B/r² ≤ eps once the grid and B are known, then applies `max_trotter_steps` and the construction limits `max_bytes` and `max_select_work`. A Method that sets both fields, or neither, is refused, and other operators refuse the tolerance because their fixed-step routes have no planning bound to invert. For heat flow on a ring, `PeriodicStencil(q, mass=0.0, diffusion=0.25)` with T = 1, `approximation_tolerance=0.005` and `trotter_synthesis_tolerance=0.005` give B = 14.02 and r = 53 at every q, with B/53² = 0.00499 and B/52² = 0.00519. The tolerance uses the frame of `approximation_tolerance`. With the default kernel-quadrature pair, whose tail and quadrature bounds fit `approximation_tolerance`, the two tolerances together bound the ideal vector error of a unit input, before native rounding and sampling. Because the bound is sufficient and not tight, a smaller r may also keep the actual synthesis error within the tolerance.

A periodic LCHS construction refusal reports the work and byte limits it exceeds. If a smaller positive step count can satisfy both limits, the message computes the largest such count `r_star` below the refused count. In automatic mode it offers an upward-rounded synthesis tolerance that selects at most `r_star` steps, provided that tolerance is finite. This clears both construction limits, but a later planning check can still refuse. In fixed-step mode the remedy is a positive integer `trotter_steps<=r_star`.

Reducing the step count increases or preserves the stated Strang bound, so it trades the construction budget against the error bound. If even one step cannot fit, only a change to the construction or its limits can resolve that refusal. The earlier automatic step-cap refusal addresses `max_trotter_steps` separately.
