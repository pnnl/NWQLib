# NWQ-Sim execution

NWQLib uses a separately built runner for the explicitly selected backend/method pair. Build and qualify the pair you intend to use before starting a [prepared workflow](prepared_execution.md).

Construct the connection explicitly; this does not launch or inspect the runner:

```python
from nwqlib.backends import NWQSimBackend

backend = NWQSimBackend(backend="CPU", method="SV", ranks=1,
    executable="/path/to/nwqlib-nwqsim", spool="/path/to/results",
    max_input_bytes=1_000_000, max_output_bytes=1_000_000,
    max_buffer_bytes=10_000_000)
```

Replace both paths with absolute paths on the execution host. The executable must be the selected qualified build; the spool holds its result files. These example byte caps are explicit limits, not measured capacity or a suitable allocation for every problem. Pass this connection to `prepare(plan, backend=backend, directory=...)` only when that native workload is intended.

## Building a selected NWQ-Sim runner

The explicit source build compiles one selected public backend/method pair from the headers in a clean NWQ-Sim checkout. It uses the existing target compiler: `c++` for CPU, `mpic++` for MPI, `nvcc` for NVIDIA, or `hipcc` for AMD HIP. It installs and downloads nothing and builds no separate VQE/frontend targets:

```bash
python -m nwqlib.backends.nwqsim /path/to/NWQ-Sim /path/to/new/nwqlib-nwqsim --compiler c++
/path/to/new/nwqlib-nwqsim --describe
# Each selected route needs its own new executable and installed toolchain.
python -m nwqlib.backends.nwqsim /path/to/NWQ-Sim /path/to/new/nwqlib-mpi --backend MPI --method SV
python -m nwqlib.backends.nwqsim /path/to/NWQ-Sim /path/to/new/nwqlib-cuda --backend NVGPU --method SV
python -m nwqlib.backends.nwqsim /path/to/NWQ-Sim /path/to/new/nwqlib-hip --backend AMDGPU --method SV
```

The output path must not already exist. The binary reports its NWQ-Sim revision, compiler, executable architecture, actual selected pair, collective support and readout kinds. Preparation checks that description against the immutable `NWQSimBackend(backend=..., method=..., ranks=..., ...)` configuration. A cross compile's executable architecture can differ from Python's host architecture. Its typed file protocol accepts Qiskit-convention U/CX instructions. Preparation lowers the logical circuit to that basis with Qiskit at the selected `optimization_level`, 0 by default. At levels 0 and 1 it first replaces each dense `UnitaryGate` by its exact synthesis (`qiskit_compat.exact_dense_unitaries`), because Qiskit's own synthesis of such a gate is not exact to rounding ([selected blocks](blocks.md#controlled-dense-unitaries)). The Run synthesizes each distinct dense matrix once per Run object and keeps its circuit for later preparations (`Run._exact_dense_unitaries`). Before each new synthesis, it sets the synthesis work aside against its `max_synthesis_work`, a total over all its preparations, and a reopened Run synthesizes a matrix and sets its work aside again. Global phase is kept for amplitude output. Counts use native sampling, while exact CPU readouts consume the existing state directly. Unsupported dynamic operations are not simulated by rerunning the circuit per shot. The per-gate print-only `PURITY_CHECK` diagnostic is disabled. Input/output byte limits and known-array limits do not claim a bound on the whole process RSS or additional SDK workspace. The runner protocol is `nwqlib.nwqsim/3`. Amplitude output uses a separate interleaved binary64 file, and a probability marginal a separate dense binary64 file of `2**k` values, one per outcome of the k observed qubits. Bit zero of a marginal index is the first observed wire. For observed wires `(0,...,k-1)`, a native basis index contributes to `x & (2**k-1)`. Unobserved high bits are summed into that bin. The native index itself is the bin only for an identity-ordered full-register observation. The result names each file with its dtype, element count and bytes, the adapter checks them before reading it, and the runner removes the files of an attempt that ends without its terminal result. The U/CX request writer checks each compact JSON gate against the byte limit before encoding or writing it. A U gate costs at most `134+digits(q)` bytes and a CX gate at most `38+digits(q0)+digits(q1)`, plus its list separator. The bytes of fixed request fields and the closing suffix are set aside separately. The writer validates finite binary64 parameters and verifies each actual encoded length against the bound.

| Backend/method | Implemented readouts | Execution boundary |
| --- | --- | --- |
| CPU/SV | Counts, Pauli expectations, probabilities, amplitudes, trajectory schedules | One process, host state access |
| CPU/DM | Counts | One process. Density matrices cannot use the SV decoder |
| MPI/SV | Counts | Cooperating power-of-two ranks, at least two local qubits each |
| NVGPU/SV or DM | Counts | One process and one visible NVIDIA GPU |
| AMDGPU/SV or DM | Counts | One process and one visible AMD GPU through HIP |
| MPI/DM | Rejected | The NWQ-Sim factory would silently substitute SV |
| NVGPU_MPI | Blocked | Inspected SV/DM constructors increment uninitialized `gpu_mem` at b35763d and at efd0226 |
| AMD GPU/MPI | Unrouted | The current public factory has no AMD GPU/MPI route |

An exact CPU/SV readout is checked, with NWQ-Sim's own per-instruction constant, against the roundoff window of its preparation record. The comment above the constants in `_validation.py` derives that constant from the fusion pass, CPU/SV kernels and U/CX matrices of revision efd0226, in `include/circuit_pass/fusion.hpp`, `include/svsim/sv_cpu.hpp` and `include/private/gate_factory/sv_gate.hpp`, and [Engineering constants](ENGINEERING_CONSTANTS.md) summarizes the derivation. The derivation also rests on the binary64 value type (`ValType = double` in `include/config.hpp` and `include/nwq_util.hpp`), the fusion switch (`ENABLE_FUSION` in `include/config.hpp`) and the gate records that the circuit builds and stores (`include/circuit.hpp` and `include/private/sim_gate.hpp`). It covers a runner whose revision is efd0226 or descends from it and whose seven files are byte-identical to those at efd0226. The file condition catches a later upstream change to any of these premises, which the revision string alone would not show. The build command decides both conditions from the NWQ-Sim checkout, and the runner's `--describe` output reports the outcome as `roundoff_base_revision` (efd0226 when the revision descends from it, otherwise null) and `roundoff_sources_identical`. The preparation record of a runner whose revision does not descend from efd0226, or whose description lacks these fields, lists "unchecked NWQ-Sim revision" in `probability_window_exclusions`. The record of a descendant with a changed file lists "changed NWQ-Sim roundoff sources". The derivation assumes IEEE binary64 arithmetic. The build command above compiles with `-O3` and no fast-math option, and a runner compiled with fast-math arithmetic is outside the derivation, although its description does not report compiler options. An efd0226 runner built with Apple clang 21 on macOS arm64 ran the default QCELS schedule of the eigenvalue notebook's eight-qubit H4 problem on nine-qubit circuits of up to 3.25 million native instructions. The probability totals differed from one by at most 5.5e-12, and no difference exceeded 1.6e-4 of the window of its circuit. For a trajectory, the CPU/SV roundoff model charges the U/CX gates actually executed through the observation, including earlier reversible readout excursions. Segment-local fusion uses no more than the charged fold and application operations. The model remains first order and subject to the record's exclusions.

Preparation asks the selected runner for its binary64 output phase factor and stores that real/imaginary pair in the request. The runner multiplies amplitude endpoints and final-boundary reduction states by that same pair. Their preparation record includes the factor's finite multiplication and modulus envelope, which `saved_state_error` and `saved_state_probability_window` propagate to consumers of those arrays. The host bound assumes round-to-nearest binary64 arithmetic, gradual underflow, and finite intermediate products and sums. The resulting state estimate remains conditional on the qualified native first-order model and measures distance modulo one common phase. The scalar factor query creates no simulator state.

`optimization_level` selects the Qiskit transpiler level of the U/CX lowering. Levels 2 and 3 resynthesize two-qubit blocks with Qiskit's own synthesis, so they receive the logical circuit as given. Without a coupling map, levels 2 and 3 can also remove SWAP and permutation gates and relabel the wires after them. Counts follow the relabeled measurements, and their preparation record stores the final layout. The adapter refuses an exact readout or a trajectory whose lowering relabeled wires, because the runner reads the state in logical wire order. At optimization levels 2 and 3, a measured circuit can supply computational-basis probabilities when lowering reports no layout. Amplitude readouts require level 0 or 1, or a circuit without measurements, because removing terminal diagonal gates can change relative phases. A level other than 0 is recorded as the exclusion `optimization_level` in the preparation record's `probability_window_exclusions`. Its `state_error()` then gives no bound, and consumers take their documented fallback. The error numbers the record still stores, such as the tolerance of its probability check, are a reference, and its native operation count describes the compiled circuit.

A CPU/SV trajectory evaluates all selected point readouts while advancing one coherent simulator state. A point's boundary precedes its reversible readout view. Pauli saves leave the state unchanged. A probability view applies its selected tail, saves the marginal, and applies the exact inverse before continuation. The preparation record counts actual native operations through the final observation, including all executed view operations, and the Run checks the summed point payloads against its limits before the trajectory runs. Trajectory readout evaluates the declared points of one deterministic, noiseless coherent evolution. Probabilities and Pauli expectations are functions of the pure state at each selected boundary. An intermediate readout view is reversed before evolution continues. The selected body and views must not introduce measurement-conditioned evolution, resets, postselection, or non-unitary channels. A registered reducer must support the selected state representation and backend. The adapter refuses a view, or the part of the body up to the last point, that contains a measurement, a reset, control flow or an opaque instruction, also inside a composite definition, before lowering. It marks each point boundary of the bound body with a labeled barrier, lowers the body through its last point to U/CX once, and reads each boundary's native gate position from its barrier; nothing after the last point runs. A view's tail is lowered once, and its inverse is the reversed, adjointed tail of that lowered sequence. The runner evolves the gates between consecutive boundaries with one NWQ-Sim call each, without resetting or renormalizing the state, and applies a view's inverse only when a later point follows. Pauli values are keyed by point and label, each marginal is a dense binary64 file and each saved state a complex128 file. A phase-sensitive intermediate output uses the running phase total of its actual boundary-preserving native construction. Scalar reducers declared invariant under one common input phase can consume raw saved amplitudes. Relative branch phases remain part of the coherent preparation. Qiskit's lowering reports one global phase for the whole lowered prefix and no phase per segment, so a reduction before the last boundary requires a reducer registered as phase invariant, and a state saved at the last boundary is multiplied, in its output copy, by the phase of the lowered prefix. Amplitude points are refused, because the detached refresh does not publish point arrays. The adapter refuses them before a preparation is charged, and it refuses such a reduction before the last point at that stage too when both positions are explicit; with the end shorthand that reduction is refused after lowering. A trajectory runs through the detached route of any other NWQ-Sim job, one evolution per execution. The trajectory's metadata check includes each point's variable envelope and the net growth of the detached outcome rows. The provider-status row is committed first and credited at outcome publication. A fresh outcome adds 161–168 JSON bytes, or 92–99 when a forecast has already revised the event, and the check sets the maximum aside. Local job identifiers are 36-character UUIDs, so each non-amplitude point's empty-value envelope costs 58 bytes. Acknowledgement and status writes use the Run's cumulative data capacity while the output bytes remain set aside. Restored readouts are checked against their actual stored rows when published. A single-endpoint probability readout, locally or through Slurm, adds the same detached outcome bytes, 168 or 99 with a forecast, to its metadata check, which refuses the readout before the runner starts when `max_completion_metadata_bytes` cannot hold it.

Every counts path uses public `measure_all` and its host outcomes. MPI's collective operation returns the same global shot population on each rank. Rank zero alone forms a histogram and publishes it: it projects each outcome onto its classical bits in the sampler's outcome array, sorts that array and counts runs, so each distinct outcome is formatted once. MPI local arrays and GPU device pointers are never dereferenced as full host states. There is no added state gather, state copy, per-term basis fallback, or second circuit evolution to obtain counts. The GPU sampler internally invokes its measurement-only kernel. The reported evolution population still names the original circuit. Exact readouts outside CPU/SV reject before preparation work. In particular, upstream AMD SV's public Z expectation covers only a finite thread prefix, and AMD DM's public Z expectation throws. Neither is used as a substitute. GPU builds enable the dependency's `GPU_ERROR_CHECK` option and their description must confirm it. CUDA/HIP allocation, copy and kernel errors then stop the native process before a completed histogram can be published. The existing dependency exits rather than throwing a C++ exception, so missing output remains uncertain after process loss. It must not trigger an automatic replacement job. On the current successful counts route this option adds three synchronization API calls and three last-error reads: one after construction and one after each of the original simulation and measurement-only kernel. Their latency is unmeasured. There is no added per-gate check, state copy or evolution.

Local MPI launch uses the configured `mpi_launcher` (default `mpirun`) with `-n ranks`. MPI is initialized before the public state factory. All ranks participate, and state destruction precedes MPI finalization. Rank-local errors abort the communicator, with no independent rank retry. The execution host or VM must remain running until completion. The contextual notice names that host and the selected result spool. A missing result remains uncertain. MPI shot counts must fit a signed 32-bit count. A U/CX gate involving a global wire also requires `2**num_qubits / ranks <= 2**31 - 1`, because the current kernel sends the entire local partition with that count type. The runner rejects an unrepresentable transfer before allocating state. Local-only gates, global measured bits and global phase do not make that state transfer.

Known state/work/sample arrays are checked against `max_buffer_bytes` **per process**. For q qubits, S shots and R MPI ranks, the current inspected allocations are:

| Route | Resident state/work arrays per process | Sample arrays per process |
| --- | --- | --- |
| CPU/SV | `24 * 2**q + 8` bytes | `8 * S` bytes |
| CPU/DM | `16 * 4**q + 8 * (2**q + 1)` bytes | `8 * S` bytes |
| MPI/SV | `32 * 2**q / R` bytes | `24 * S` bytes |
| GPU/SV | `48 * 2**q + 16` bytes, host plus device | `32 * S` bytes, host plus device |
| GPU/DM | `48 * 4**q + 16` bytes, host plus device | `32 * S` bytes, host plus device |

CPU probability readout additionally uses `16 * 2**k` bytes for its k-bit marginal, and its binary result file holds `8 * 2**k` bytes, which count against the output limit. The runner releases the parsed gate array once the native circuit holds the gates, before it allocates the state. Fused gates, the parsed input's other fields, native circuit copies, runtime allocations, MPI communication buffers and extra SDK workspace are outside this known-array inventory. Additional workspace remains unknown. Each rank holds its own input and circuit, and the transport check counts one input write plus R reads. Aggregate MPI arrays sum over R processes, while shots and original evolutions are counted once. The native MPI sampler scans global indices and compares each local state's probability interval with S samples. These source-level costs are not a measured scaling guarantee.

For a 20-qubit example, known SV state/work arrays are about 24 MiB on CPU, 8 MiB per rank with four MPI ranks, or 48 MiB across host and device on one GPU, before samples and excluded workspace. Twenty-qubit DM instead requires about 16 TiB on CPU or 48 TiB on GPU. These are scalar projections, not allocations or workload qualification. A small passing simulation cannot establish that capacity or runtime.

The inspected NWQ-Sim revision `b35763d846e6512ed817d3f88ac8ce79a7e82a7e` has undefined behavior in its CPU constructors: each increments an uninitialized memory counter. Its U matrix factory can also overflow the sum of finite phases. Python preparation rejects this known unqualified revision before lowering or execution. Restrictions on circuit angles cannot repair the constructor defect. The build helper records the exact revision and leaves that checkout untouched. It does not establish qualification, and direct runner CLI callers remain responsible for selecting a qualified revision.

Upstream revision `efd02262ff9c5def4f2eac1df6416c1ee2023d5b` initializes the CPU memory counters and composes finite U phases without overflowing their sum. It also stores the CU gate's gamma phase, which the NWQLib runner does not use because it sends only U and CX instructions. Its CPU/SV runner, built with g++ 14.2.0 on Linux aarch64, passed NWQLib's native CPU/SV tests and a public-route exact Pauli expectation. A revision that descends from efd0226 and keeps the seven roundoff source files above unchanged is qualified for CPU/SV by the same rule as the roundoff window. A CPU/SV runner built from upstream `202f5cab03477c78ab9f0b4dbbbf8f135778ac8f`, whose `include/` tree equals that of efd0226, passed the same checks with g++ 14.2.0 on Linux aarch64, and the preparation record of its exact Pauli expectation listed no exclusion. This rule qualifies CPU/SV builds and no other backend or method. NWQLib does not distribute or apply a dependency patch. The unpatched revision `b35763d` remains unqualified. A revision outside the rule requires its own review and explicitly authorized numerical checks. Acceptance of a revision string is not qualification. The supported finite U-angle domain is unchanged. The runner claims an output directory before execution and publishes files without overwriting existing results. A process crash can leave an output `.claim` directory. Reconcile that attempt before deciding whether another execution is needed. Normal failures clean this attempt's staged artifacts and keep a bounded failure result when writable. If execution started and no terminal result can be written, the claim remains for reconciliation. A qualified runner and its low-level checks alone do not establish a complete scientific workflow or another backend/method combination.

The local MPI evidence consists of two four-qubit, two-rank, 32-shot checks using an x86_64 executable translated on an arm64 macOS host. They cover a public detached parity workflow and cross-rank Bell sampling with an unequal classical-bit map. GPU/DM routes have source and offline wiring evidence only. No GPU toolchain, hardware, or live site was qualified by those checks.

`NWQSimSlurmBackend` composes this same selected preparation and native result decoder with Slurm through the common detached workflow. See [Slurm execution and site handoff](slurm.md) for its explicit profile, accounting window, journal/resume behavior and GPU/MPI limits.

For local execution, `Run.cancel()` records the cancellation request and refuses new preparation or measurement in that Run. `NWQSimBackend` has no process cancellation operation, so a local NWQ-Sim process that has already been launched can keep running until it finishes. The Run adds a process-local notice to `run.warnings` that the original job remains observable, and a later `Run.resume()` of the same Run can still read the process's result file if one is written.

Detached result spools are addressed by the original submission identity and remain separate from the Run journal. Spools can accumulate across runs, and the Run data limit does not cap that aggregate filesystem population. NWQLib has no spool-cleanup operation. Cleanup would require confirmed terminal jobs, all observations durably collected, and no remaining retrieval or reconciliation consumer. Pending, uncertain, incomplete, unconfirmed cancellations and foreign paths must keep their original data.

If a local launch intent loses its acknowledgement, automatic waiting requires either the original observable child process or a terminal result file. A spool directory alone does not establish that the process started. Without either form of progress, `resume()` and `wait()` raise `RunFailed` with status `uncertain`, preserving the original identity and `run.exposure`. A later explicit `resume()` can still collect output that arrives at that same path. The adapter checks file metadata and an existing child handle through `can_reconcile`, without a replacement launch or refund.
