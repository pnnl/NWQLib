# IBM Runtime execution

Install the `ibm` extra and configure an explicit connection for the selected IBM device and instance. Configuration is immutable. Preparing or refreshing a workflow loads the SDK and uses its configured credentials. With `account_name` supplied, the adapter uses that saved SDK account. Otherwise it reads the variable selected by `token_env`, whose default is `NWQLIB_IBM_RUNTIME_TOKEN`; it does not store the token in Run records.

```python
from nwqlib.backends import IBMRuntimeBackend

backend = IBMRuntimeBackend(
    device="YOUR-IBM-DEVICE", instance="YOUR-IBM-INSTANCE",
    max_input_bytes=65_536,
)
```

Pass this connection to `nwqlib.prepare(plan, backend=backend, directory=...)`, then call `nwqlib.submit(prepared)` and continue through the returned Run. [Run archives](run_archives.md#save-and-reopen-pending-work) show how to save that Run and reopen it later. Offline SDK and transport checks do not qualify a live account, queue or QPU.

## IBM Runtime prepared execution

`IBMRuntimeBackend` connects an explicit device and instance to the shared `prepare`, `submit_detached`, and `refresh_submissions` workflow. Its constructor does not read credentials or contact the service. Select a saved account name or the credential environment variable. Secrets are excluded from stored records. Preparation transpiles to the selected ISA and keeps the logical to physical layout, requested options, and SDK versions. At optimization levels 0 and 1 it first replaces each dense `UnitaryGate` outside control-flow blocks by its exact synthesis ([selected blocks](blocks.md#controlled-dense-unitaries)). The Run synthesizes each distinct dense matrix once per Run object and keeps its circuit for later preparations (`Run._exact_dense_unitaries`). Before each new synthesis, it sets the synthesis work aside against its `max_synthesis_work`, a total over all its preparations, and a reopened Run synthesizes a matrix and sets its work aside again. Levels 2 and 3 resynthesize two-qubit blocks with Qiskit's own synthesis, so they receive the logical circuit as given. In Qiskit 2.5.2, the `TwoQubitPeepholeOptimization` pass of those levels changes the global phase by pi for some CX patterns on targets whose two-qubit gate is CX, which leaves counts and expectation values unchanged ([dependency issues](dependency_issues.md)). Level 1, the default, does not run that pass. A level other than 1 is recorded as the exclusion `optimization_level` in the preparation record's `probability_window_exclusions`, which marks a circuit compiled at a non-default level, and the operation count describes the compiled circuit. The IBM target has no derived roundoff constant, so `state_error()` gives no bound at any level. The durable Run keeps QPY before submission so a prepared but unused circuit can survive interruption. Subsequent retrieval uses the original job and does not serialize that circuit again. Resuming a known job uses its original locator without recompiling or submitting another job. Native journal payloads have ordinary local IDs and preserve the saved bytes. They are not content-hashed or authenticated. Editing saved native data does not cause an archive-level mathematical-assumption check. Previously submitted jobs and their returned results still describe their original executions. Failed retrieval records the original job state and propagates the original exception, including its traceback. A later explicit refresh can retrieve the same job. Decoder errors are not swallowed as normal pending states.

Every job carries the tag `nwqlib:<submission UUID>`. If its job ID never reaches the journal, because the process stopped or `launch` raised after the request was sent, the submission stays uncertain and charged, and the next refresh calls `reconcile`. That call asks the service for at most two jobs with the tag on the configured device, instance and primitive. One match that passes the identity checks becomes the saved locator. No match leaves the submission unresolved, and two matches raise, because neither case identifies the original job and neither permits a new submission.

SamplerV2 returns joint classified counts. Each PUB keeps its original item coordinate, including when one prepared circuit appears more than once. Named classical registers are joined by shot before restoring logical bit order. Physical measurements are distinct populations. Fixed simulator seeds identify known repeated data and do not establish independent observations.

Each scalar Sampler PUB's live ndarray element bytes, including the selected packed register inputs, are checked against `sampler_decode_bytes` before joining. Up to 64 classical bits, the bound covers the packed join, uint64 shot arrays and sorted unique/count workspace, and the backend returns one uint64 index and one int64 count per distinct outcome. Above 64 classical bits, it checks the padded-join array bound listed in [Engineering constants](ENGINEERING_CONSTANTS.md) against that limit and returns bit-string count keys. The subsequent conversion of packed rows to Python bytes, integers, strings and count dictionaries adds no ndarray element buffers. The shared decoder checks either representation against the prepared readout cardinality and constructs the public count records. This per-PUB array limit is separate from the cumulative stored-data check and does not bound Python object memory, Runtime transport or whole-process memory.

For finite-Pauli expectation, `ExpectationMethod.estimate_precision` selects EstimatorV2. The full weighted observable, including identity terms and small coefficients, follows the circuit's physical layout. The returned signed estimate is kept without clipping. Provider `stds`, optional ensemble standard error, requested settings, and returned metadata are kept separately. Without ZNE, documented `stds` can supply the sampling standard error. With ZNE it describes fit uncertainty and is not presented as sampling SEM or a physical bias bound. Missing or ambiguous uncertainty stays unavailable. Provider-managed shots are unknown to the raw-shot limit, so that limit does not cap Estimator spending. The default resilience level is zero. Other supported options require explicit selection. Experimental overrides are rejected before preparation.

Job mode is the default. Session and Batch modes attach only to an explicitly selected existing container. A run cancellation stops new work. The next explicit refresh requests cancellation once and later provider status confirms the outcome. Cancellation does not refund the jobs or shots set aside. A failed or interrupted cancellation remains a request, and is not automatically repeated.

The Runtime 0.49 transport was checked through a local HTTP server using the actual SDK client, primitive, job, and decoder. A lost POST acknowledgement was not resubmitted. Tag-based reconciliation recovered the original job. The SDK retries certain 5xx POST responses under IBM's documented safe-retry contract, and permits at most five retries per HTTP request, with at most three connection retries. A rejected 503 followed by success and a retried GET were checked. These fixtures establish client behavior, not server billing or hardware accuracy. Internal SDK buffers, read timeout, compilation memory, and total network traffic are not bounded by the wrapper's metadata limit. Later SDK versions need the same transport qualification before inheriting these claims.
