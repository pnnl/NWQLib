# Selected semantic blocks

`nwqlib.blocks` constructs selected block records without importing Qiskit, backend providers or native algorithm implementations. Selection is actual bounded construction work: the selected input/array owner checks its concrete `max_bytes` limit before the required conversion. Reading metadata alone does not grant executable access or trigger coefficient scanning.

The [example below](#compose-and-lower-a-pauli-encoding) selects occupation PREP with the `native` X recipe and the `hzh` recipe, then builds, round-trips through JSON and explicitly lowers a three-qubit encoding of `A = -2X + Y + 3I`. Its projected block is `A/6`.

## Selected action and identity

`select_preparation` consumes an accepted `StateInput`. It keeps the physical input identity, positive norm, computational ordering and physical global phase. The promise is `U|0> = input / norm`. The selected extension determines `U` on other inputs, its inverse, and its coherent control. X and HZH agree as full operators. Arbitrary preparations of the same state need not share that stronger relation. Occupation strings remain q0-first: `"10"` prepares the printed ket `|01>` on two qubits.

`select_signed_pauli` consumes accepted Hermitian Pauli terms without centering, coefficient pruning, or dense expansion. The physical normalization is `alpha = sum(abs(c_j))`. Label qubits precede system qubits, with q0 rightmost within each register. The selected action is `SELECT = sum_j |j><j| tensor sign(c_j) P_j`, written with the label register first as the papers do. Because the label qubits are the low-order qubits, a Qiskit dense matrix of the block, whose qubit 0 is the least significant index, reads `sum_j sign(c_j) P_j tensor |j><j|` ([FRAMEWORK](FRAMEWORK.md#block-encoding-and-qsp-conventions)). Unused labels have identity action. `select_pauli_preparation` explicitly accepts the coefficient vector and selects its input preparation. Its existing coefficient vector enters the bounded StateInput owner once. Selection does not synthesize the PREP circuit. Padding amplitudes are zero. Single-term input has no label register or PREP. Identity-only input is legal. Zero input is accepted by the input owner but cannot define this positive-alpha encoding.

`PauliEncoding` identifies a shared Sequence containing this coefficient PREP, SELECT, and the selected PREP inverse. Validation checks their native selection references, order, and index-register mappings. `encoding_semantics(root)` derives `(A, alpha, index-zero projector, epsilon)` from that same selected SELECT. The index register is **not** promised to return to zero unconditionally. Projecting onto zero succeeds with probability `||A psi||² / alpha²` for normalized `psi`. `select_zero_reflection` has the Lanczos sign `2|0><0|-I`, including identity on an empty register.

`transform_block` selects one coherent control, an adjoint, or both. Control is the first whole-register port. The phase-preserving native control and inverse helpers act on the chosen extension, including its global phase. A transformed selection cannot be transformed again. Trusted method-owned constructors can use this operation when their selected contract permits control or inverse. The effective unitary-transform contract keeps `base_semantics` separately. Its full-operator approximation is unknown. A zero-input state error or projected block error is not promoted to an inverse/control operator bound.

`select_pauli_readout` reuses the accepted signed SELECT input for the existing label-controlled basis rotation: H for X, H S† for Y, identity for Z/I/padding. The classical outcome is coefficient sign times non-I parity on used labels and zero on padding, without postselection. Thus `V† D V = Pi_used SELECT Pi_used`. The identity extension of unitary SELECT does not make a padding event count +1. The algorithm keeps ownership of decoding those outcomes.

`SelectedBlock` is an immutable native owner. Method authors use `SelectedBlock.bind(record, payload=inputs, constructor=build)` to bind trusted code to its exact selected definition and accepted inputs. The constructor receives `(block, arguments, method_context)` and returns a circuit. Common lowering checks the selected identity, argument domains and dynamic-operation/width limits before calling it; each expensive constructor owns its concrete numerical/synthesis controls. Adding a method requires no shared implementation registry. The record can be serialized or revised independently. That operation neither changes an existing binding nor recreates executable access.

The constructor must implement its versioned definition, including its scientific dependencies and work law. Its context getter supplies the existing lazy method-owned context. Constructors must not keep the getter or Run. Control and adjoint bind the exact live base through `transform_block`, so the realized base gate and its full phase remain authoritative. A blocked leaf may carry no constructor, but cannot execute. `SelectedBlock.bind` performs no SDK import or circuit construction.

`select_preparation` binds supplied `qiskit.supplied` inputs as the distinct selected implementation `preparation.supplied`. Each choice has a fresh factory identity. A matching declared input name or portable record cannot reattach another native circuit. The supplied choice has no decomposition, CX cost law, or resource laws, and its approximation error is unknown. Control and inverse preserve that uncertainty rather than inheriting a direct-state preparation law. Snapshot data bytes are bounded separately from unknown native synthesis and allocator costs. Stored numerical profiles must cover the actual selected identity. Execution capability separately checks the declared implementation/primitive support.

Supplied preparation and supplied BlockEncoding share the same native intake. Gate-based `AnnotatedOperation` data keep ordered control, inverse and finite real powers, including fractional, negative and zero powers. Intake copies the stored base and modifier data with memoized sharing and active-ancestor cycle checks. It does not expand powers or call control/inverse/power synthesis. Modifier list/node slots and control-bit storage are checked against their limits before allocation, and arrays keep the existing finite-data and cumulative copy budgets. The actual common native preparation boundary performs its selected HLS work. Unknown HLS expansion cost is separate from the logical snapshot census. Unknown implementations and laws remain representable as records. Their missing executable binding is a blocker. Persisted references never import arbitrary modules or execute a callable. A later persistence owner must explicitly restore native access. A JSON record alone is not a quantum oracle.

## Compose and lower a Pauli encoding

The first two selections prepare `|1>` with the X and HZH recipes. The encoding then places the coefficient PREP on two index qubits, which address the three terms and one zero-amplitude padding slot, and SELECT on one system qubit:

```python
from nwqlib.blocks import (
    PauliEncoding, SelectedConstruction, lower_qiskit,
    select_pauli_preparation, select_preparation, select_signed_pauli, transform_block,
)
from nwqlib.ir import Allocate, BlockCall, Definition, PortMap, Program, Register, Sequence
from nwqlib.operators import ingest_pauli
from nwqlib.problems import ingest_occupation

state = ingest_occupation("1", num_qubits=1)
x_prep = select_preparation("prep", state)                  # recipe x
hzh_prep = select_preparation("prep", state, choice="hzh")  # recipe h, z, h

select = select_signed_pauli("select", ingest_pauli([("X", -2), ("Y", 1), ("I", 3)], num_qubits=1))
prep = select_pauli_preparation("prep", select)
blocks = (prep, select, transform_block("unprep", prep, adjoint=True))


def call(name, **ports):
    return BlockCall(signature=name, ports=tuple(PortMap(port=p, wire=w) for p, w in ports.items()))


nodes = {
    "index": Allocate(wire="index"),
    "system": Allocate(wire="system"),
    "prep": call("prep", system="index"),
    "select": call("select", index="index", system="system"),
    "unprep": call("unprep", system="index"),
    "encoding": Sequence(children=("prep", "select", "unprep")),
    "root": Sequence(children=("index", "system", "encoding")),
}
construction = SelectedConstruction(
    program=Program(
        root="root",
        registers=(Register(name="index", width=2), Register(name="system", width=1)),
        signatures=tuple(block.record.signature for block in blocks),
        definitions=tuple(Definition(id=key, node=node) for key, node in nodes.items()),
    ),
    selections=tuple(block.record for block in blocks),
    encodings=(PauliEncoding(root="encoding", select="select", prepare="prep", unprepare="unprep"),),
)
print(construction.encoding_semantics("encoding").alpha)  # 6.0
assert SelectedConstruction.model_validate_json(construction.model_dump_json()) == construction
logical = lower_qiskit(construction, blocks=blocks, max_operations=1024, max_qubits=3, max_clbits=0)
```

The port maps connect the PREP `system` port to the index wire and the SELECT ports to the index and system wires. The JSON round trip keeps the selected identity, while native access stays with `blocks`. Only `lower_qiskit` builds a Qiskit circuit. `nwqlib.resources.estimate(construction)` folds the same body without lowering it.

## One graph and scoped costs

`SelectedConstruction.program` is the existing shared `Program` DAG. Sequences, shared calls and compact Repeat keep ordering and multiplicity. There is no second algorithm graph, `Plan` identity, or resource-fold engine in this layer. Exact basis, occupation and full-uniform preparations expose ordered primitive recipes. Other leaves point to their selected numerical/circuit law. Generic vector, contiguous-prefix uniform and product preparation remain distinct choices. Product law parameters mean q applications of a **one-qubit** law. They do not price a full `2**q` vector. A controlled selection switches the relevant law and preserves its parameters.

Exact primitives, native CX slot bounds, selected construction size laws and physical hardware cost are different quantities. Control includes single-qubit operations and phase/projector work. Law context and unknown cost must be carried by the later resource fold. An absent law is never zero. The shared SDK-free preparation laws are the same functions used by the numerical circuit builders. They are bounds where declared, not measured compiled inventories. Neither selection nor a resource-law lookup synthesizes or simulates a circuit.

`epsilon=0` for the supported exact recipes means no algorithmic approximation in the ideal-gate relation. Floating synthesis roundoff is not bounded by this record, and no hardware fidelity or global algorithm accuracy is implied.

## Explicit logical lowering

`lower_qiskit` supports static Sequence, concrete/bound Repeat, coherent regions, known BlockCall with accepted concrete arguments, allocation/release, computational measurement and reset. Whole registers appear in declaration order and the returned `LogicalCircuit` supplies both quantum and classical layouts. The circuit keeps all declared registers. `Program.select_experiment` selects one root batch setting and its bindings. That selected Program lowers directly. Multi-setting or nested batches, dynamic branches, classical stages, adaptive loops and reallocation require another selected consumer and fail explicitly.

`lower_qiskit` checks `max_operations=100_000` dynamic IR visits, `max_qubits=4096`, `max_clbits=4096` and the amplitude count of each reachable block that declares a direct state preparation against `max_direct_amplitudes=65_536` before SDK import or instruction emission. A Run passes its `ExecutionLimits.max_direct_amplitudes`. Before `lower_qiskit` controls the realized base of a controlled transformed block, it adds the work of the exact syntheses and of Qiskit's control of them to a total that `max_synthesis_work=1_000_000_000` bounds, and a Run charges that work to its `ExecutionLimits.max_synthesis_work` instead ([limit checks of the exact synthesis](#admission-of-the-exact-synthesis)). Width limits are nonnegative, and the operation limit is positive and inclusive. Unused definitions and zero-count bodies are not built. Huge Repeat counts are checked by compact arithmetic, while empty bodies still consume traversal visits. Native definitions are cached by exact selected identity and, for parameterized calls, formal-order arguments. Static forward and inverse uses share their native base, and parameterized transforms require a supported compact constructor. `construction_work` reports the selected size-law sum, which is not an aggregate funding cap or measured execution. Each numerical/native constructor applies its actual cost controls. `defined_selections` lists used definition templates, while the Program keeps actual call bindings. A coherent circuit is never split across jobs.

The output is a logical Qiskit circuit, without compilation, backend execution, or QASM export. The default QASM3 writer remains a separate downstream consumer.

## Adjoint multiplexers

An uncontrolled, complete multiplexer can be adjointed by conjugate-transposing each stored target matrix and keeping the same address order. Aer applies that table directly when its target supports the native `multiplexer` instruction (Aer 0.17.2 `QubitVector::apply_multiplexer`, [source](https://github.com/Qiskit/qiskit-aer/blob/0.17.2/src/simulators/statevector/qubitvector.hpp#L1306-L1342)). The table route copies each conjugate-transposed 2×2 entry, allocating `64 * 2**k` new array bytes for `k` controls, and forms no dense operator. The adjoint identity holds for the stored matrices. Equality to an inverse also requires unitary table blocks, so a native forward/adjoint pair has the table's Gram defect in addition to execution error.

An outer control expands the multiplexer into a gate circuit. QSP evolution and controlled QLS queries therefore construct the inverse by reversing the realized forward definition before copying repeated child queries. This reuses the forward UCG synthesis. Gate-wise control still processes each query occurrence. Uncontrolled native consumers, including Lanczos readout and direct block adjoints, keep their adjoint tables.

`inverse_realized_gate(..., native_ucg=False)` selects the reversed-definition route when a caller knows the inverse will be controlled or decomposed. With `native_ucg=True`, native execution remains conditional on the later transformations and backend target. A backend that decomposes an adjoint table constructs a separate numerical synthesis whose error must be assessed in that representation.

## Controlled dense unitaries

Native control in lowering, the controlled constructions of LCHS, QLS and QSP, the dense LCU SELECT and the QPE powers all call `subroutines/qiskit_compat.controlled`. Qiskit 2.5.2 controls a composite gate by unrolling its definition and controlling each gate, and it unrolls a dense `UnitaryGate` on two or more qubits through its own synthesis, which is not exact to rounding. That synthesis replaces the Weyl coordinates of a two-qubit unitary by those of a special class whenever the average gate fidelity of the replacement is at least `1 - 1e-9`. A two-qubit unitary close to the identity thus loses its entangling part, with entry errors measured up to 4.2e-5 ([dependency issues](dependency_issues.md)). Qiskit's quantum Shannon decomposition also omits multiplexed rotations of at most 1e-10 rad. `controlled` therefore first replaces each such unitary in the definition, at any depth, by the circuit of `subroutines/_dense_synthesis.dense_unitary_circuit`, which equals it to rounding. A two-qubit unitary uses its KAK decomposition in the magic basis and at most three CX. A larger one uses the block-ZXZ quantum Shannon decomposition down to two-qubit blocks, with the CX savings of Krol and Al-Ars, arXiv:2403.13692v2, and optimization A.2 of arXiv:quant-ph/0406176v5, and a generic n-qubit unitary then takes `(22/48) 4**n - (3/2) 2**n + 5/3` CX, the same count as Qiskit's `qs_decomposition`. A two-qubit block with a small second Weyl coordinate can keep one more CX, because A.2 cannot remove its last coordinate exactly. Only a Weyl coordinate, a one-qubit gate or a block entry within `2**-46` of zero, of the identity or of an exact special value is replaced by that value, and each replacement changes the operator by an amount of that order (`ROUNDING_WINDOW`, [engineering constants](ENGINEERING_CONSTANTS.md#numerical-guards-and-tolerances)). `tests/test_dense_synthesis.py` checks the entry error for one to five qubits, the CX counts and the special classes, and `tests/test_scientist_lchs.py` compares controlled LCHS branches with SciPy exponentials.

A `UnitaryGate` that is controlled directly, as in the dense LCU SELECT, the dense QPE powers and the coherent QPE powers, is synthesized from its whole controlled matrix by `subroutines/_dense_synthesis.controlled_unitary_circuit`. Qiskit's own `UnitaryGate.control` synthesizes the same matrix by quantum Shannon decomposition and keeps the result when `numpy.allclose` with `atol=1e-7` and `rtol=1e-5` accepts it, and otherwise falls back to an `Isometry` circuit. For one-qubit X, Y and Z rotations by 1e-8 to 1e-2 with one to three controls, the kept results erred by up to 7.9e-6 per entry, and for `RX(1e-7)` with three controls the fallback raised `ValueError`. The controlled matrix is block diagonal with respect to each control qubit, so the exact synthesis demultiplexes it at the top (Shende, Bullock and Markov, arXiv:quant-ph/0406176v5, Theorem 12) and synthesizes the two halves without A.2. On m >= 3 qubits this takes at most `(25/96) 4**m - 2**m + 4/3` CX, the largest count that Qiskit 2.5.2 reached for the same controlled matrices in tests, and at most `(11/16) 4**m - 2**(m+1)` instructions. A base matrix that is not unitary to rounding is realized as its unitary polar factor, which differs from it by the order of its unitarity defect. Controlling each gate of the synthesized base unitary instead takes about four times as many CX with one control, the case of every QPE power. In tests on up to seven qubits it took fewer only with four or more controls, for example 1476 instead of 4140 CX for a two-qubit branch with five controls. For `U = expm(-i t G)` with t from 1e-10 to 10, one to three system qubits and one to three controls, the entry error stayed below 4.1e-14, also after lowering to U and CX. `subroutines/_dense_synthesis.controlled_synthesis_size` derives the work and bytes that the LCU and QPE limit checks and the coherent QPE builder charge for this synthesis. `inverse()` of the resulting gate follows Qiskit's `ControlledGate.inverse` and synthesizes the adjoint through `UnitaryGate.control` again, while `subroutines/qiskit_compat.inverse_realized_gate`, which lowering uses for adjoint blocks, reverses the exact definition.

An uncontrolled `UnitaryGate` stays a matrix in the logical circuit, and Aer applies that matrix directly. Before compiling, the Nexus preparation, NWQ-Sim, IonQ with its QIS gateset and IBM at optimization levels 0 and 1, and Aer with a noise model whose gate basis omits the unitary instruction replace each dense `UnitaryGate` outside control-flow blocks and annotated operations by the same exact synthesis (`qiskit_compat.exact_dense_unitaries`). Optimization levels 2 and 3 of NWQ-Sim, IonQ and IBM resynthesize two-qubit blocks with Qiskit's own synthesis, so they receive the logical circuit as given, and remote compilers such as Nexus apply their own passes. The MPS state preparation (`subroutines/state_preparation/mps_circuit.py`) synthesizes its two-qubit gates with `dense_unitary_circuit` too.

### Dense control route

In `LCHS`, `QLS` and `build_control_diagonal_generator_encoding`, the `dense_control_route` option selects one of two routes by which a construction adds controls to a dense unitary on two or more qubits (`subroutines/_dense_synthesis.select_dense_control_route`). The gate-wise route (`"gatewise"`) synthesizes the unitary with `dense_unitary_circuit` and lets Qiskit control each synthesized gate. The whole-matrix route (`"whole_matrix"`) synthesizes the controlled matrix with `controlled_unitary_circuit`, as a directly controlled `UnitaryGate` does. The default `"auto"` takes the whole-matrix route for one control and the gate-wise route for two or more (`AUTO_WHOLE_MATRIX_MAX_CONTROLS`, registered with its derivation in [engineering constants](ENGINEERING_CONSTANTS.md#circuit-free-synthesis-laws)). The option is part of the Method and of the `Plan`'s identifier, and planning, the limit checks, the resource laws and lowering read the same route. For Haar-random unitaries on 2 to 5 qubits (Qiskit 2.5.2) the whole-matrix route took 3.2 to 4.0 times fewer CX than the gate-wise route with one control, 3.6 to 3.8 times fewer with two and 1.9 to 2.1 times fewer with three. Its classical work, about 88 M**3 units with one control against about 28 M**3 for the synthesis of the M-square unitary alone, grows about eight times and its bytes four times per added control. Both routes give the controlled matrix to rounding (`tests/test_dense_control_route.py`).

The route applies to three constructions that hold the dense matrix: an LCHS `dense_exact` branch on its address bits, the controlled QLS query of a planned dense dilation and a `dense_dilation` child that the combine qubit of a two-child joint generator controls. On the whole-matrix route an LCHS constant-source branch is one unitary, its evolution times the matrix of its input preparation, and a joint-generator branch is controlled part by part, the child through its controlled dilation and the diagonal rotation gate-wise, with the branch's global phase as a phase gate on the control (`qiskit_compat.controlled`). A one-qubit unitary keeps Qiskit's exact definition on both routes. A supplied circuit, such as a native encoding, a supplied preparation or the ADAPT reference, is controlled gate-wise on every route, because its matrix is not known and it may hold operations without one. The parity control of a QSP pass controls the whole pass and is gate-wise on every route.

### Admission of the exact synthesis

`subroutines/_dense_synthesis.dense_synthesis_size` gives the work and bytes of one `dense_unitary_circuit` on m qubits, `113 M**3/4 + (m**2 + 16 m + 512) M**2` units, `320 M**2 + 65536` working bytes and `352 M**2 + 16384` kept bytes with M = 2**m, derived in its docstring and registered in [engineering constants](ENGINEERING_CONSTANTS.md#circuit-free-synthesis-laws). `controlled_synthesis_size` gives those of a directly controlled matrix. `subroutines/qiskit_compat.dense_synthesis_widths` lists the syntheses that a rewrite would make, without making them. A Haar-random unitary on 8 qubits took 0.57 s and one on 9 qubits 2.6 s on one core.

On the gate-wise route, when a construction controls a composite gate that holds dense unitaries, `qiskit_compat.controlled` replaces each by its exact synthesis, and Qiskit then controls every synthesized gate, once for every place where the synthesis occurs in the gate. This control step has its own law, the gate-wise control law of `gatewise_control_counts` and `gatewise_control_size`. For one synthesis on m qubits with k controls, `gatewise_control_counts` bounds the gates that Qiskit unrolls (the census of `dense_synthesis_gate_census` plus the global phase), the instructions that it emits and the heavy instructions among them, which hold angles or are Python objects. Qiskit 2.5.2 turns a U gate into 1, 21, 86, 193 and 829 instructions with 1, 2, 3, 4 and 8 controls and an RZ into 1, 8, 36, 64 and 276, and a CX or the global phase into one and an H into seven for every k (`CONTROLLED_U_INSTRUCTIONS` and `CONTROLLED_RZ_INSTRUCTIONS` store these counts for 1 to 64 controls). `gatewise_control_size` charges 2048 units of planning work for each unrolled gate and 16 for each emitted instruction. Its kept-byte law allows 96 bytes for each instruction and 1024 more for each heavy one. `qiskit_compat.dense_control_counts` adds these counts over the occurrences of the dense unitaries in a gate. For Haar-random syntheses on 4 to 7 qubits with one to eight controls (Qiskit 2.5.2, Apple-silicon Mac, one thread), the law counted 1.0 to 1.19 times the emitted instructions, and Qiskit's control call took 4.4 to 35 ns per unit of planning work against 1.6 to 15 ns per unit for the synthesis itself. Both laws feed the same limits, which count units of planning work, not time. Together, the kept-byte laws of the synthesis and of this step allowed at least 1.7 times the memory that the kept controlled gates held, and the working and kept bytes of this step allowed at least 2.1 times the peak increase of resident memory during the call, wherever that increase exceeded 0.1 MB. For a random 512 × 512 unitary, the size of the dense dilation of a 256-dimensional QLS system, Qiskit's control took 3.8 s with one control and 27 s with two, and the controlled circuit held 391,679 and 2,914,498 instructions (Qiskit 2.5.2, Apple-silicon Mac, one thread), where the law counts 424,445 and 3,400,957. Basis lowering synthesizes through `Run._exact_dense_unitaries`, which keeps the circuit of every synthesis until the Run is closed, keyed by the shape, dtype and bytes of its matrix. A later preparation that holds the same matrix, even in new gate objects, receives a copy of that circuit, which equals a new synthesis because the synthesis is deterministic. A reopened Run starts with an empty cache. The Run reserves the syntheses that basis lowering or a controlled transform makes on the charge of the preparation that makes them, in one journal commit for each batch before its first synthesis starts. A dense unitary becomes known only when the `Plan` is lowered, which follows the preparation charge, so a refusal of its synthesis comes after that charge. The refused preparation stays charged against `max_total_circuits` and leaves its experiment unprepared. After `run.extend_limits(max_synthesis_work=...)` raises the limit, the next call of the static workflow or of the Method's controller prepares the experiment again.

Qiskit also controls the other gates of a controlled composite, such as the projector phases and multiplexors of a QSP pass or the input preparation of a controlled LCHS source branch, and a backend later lowers the controlled circuit to its gate basis. These costs lie outside the laws above, and [ROADMAP](ROADMAP.md#controlled-dense-query-construction) keeps them open.

## Bounded evidence

The targeted tests use at most three qubits. Independent amplitudes expose the controlled `-X` phase, complex preparation/inverse ordering, reflection sign, negative/Y/identity projected action and identity padding. Hand-counted X/HZH inventories distinguish selected recipes. The generic controlled preparation uses an inequality against the native slot bound. Fresh-process import-attempt checks include a deliberately swallowed SDK import, and materialization/input checks preserve legal low-work counterparts. These checks do not establish a large-system performance or hardware claim.

## Resource consumer

The [selected resource fold](resources.md) consumes these same portable records. SelectedDefinition can keep scoped per-metric ResourceLaw declarations and per-invocation Workspace declarations. A law-only FT selection remains a legal conditional estimate without a native executable binding. Primitive arity and concrete target bounds are checked at the selected-record owner. The existing logical lowering rejects Parallel. Dependency-aware resource support alone does not create a compiler implementation.
