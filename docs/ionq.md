# IonQ execution

`nwqlib.backends.ionq.IonQBackend` binds an explicit v0.4 QPU device to the common `Run`, `prepare`, `submit`, `submit_detached` and `refresh_submissions` path. Configuration is immutable and does not import the provider SDK or contact IonQ.

```python
from nwqlib.backends.ionq import IonQBackend

backend = IonQBackend(
    device="qpu.forte-1",
    gateset="qis",
    debiasing=False,
    max_input_bytes=1_000_000,
    max_response_bytes=1_000_000,
)
```

Supply this configuration as `backend=backend` on the common run. Set `NWQLIB_IONQ_API_KEY` only when explicitly executing or retrieving a job. Credentials are not stored in the configuration, preparation record or journal. Choose ExecutionLimits for the actual workload. These example values are limits, not provider cost estimates.

The adapter uses the public `qiskit_ionq.helpers.qiskit_circ_to_ionq_circ` converter. QIS circuits use Qiskit's public transpiler with the Rx/Ry/Rz/CX basis at the selected `optimization_level`, 0 by default. At levels 0 and 1 each dense `UnitaryGate` is first replaced by its exact synthesis (`qiskit_compat.exact_dense_unitaries`), because Qiskit's own synthesis of such a gate is not exact to rounding ([selected blocks](blocks.md#controlled-dense-unitaries)). Levels 2 and 3 resynthesize two-qubit blocks with Qiskit's own synthesis, so they receive the logical circuit as given. A level other than 0 is recorded as the exclusion `optimization_level` in the preparation record's `probability_window_exclusions`, which marks a circuit compiled at a non-default level, and the operation count describes the compiled circuit. The IonQ target has no derived roundoff constant, so `state_error()` gives no bound at any level. The native gateset is converted without Qiskit lowering and accepts only level 0. The Run synthesizes each distinct dense matrix once per Run object and keeps its circuit for later preparations (`Run._exact_dense_unitaries`). Before each new synthesis, it sets the synthesis work aside against its `max_synthesis_work`, a total over all its preparations, and a reopened Run synthesizes a matrix and sets its work aside again. QIS rotations remain in radians. Native SDK gates are passed to the converter without changing their turns-valued parameters. The flat circuit route requires final measurements and preserves each measured quantum wire's classical-bit destination. Unmeasured classical bits remain zero. It does not offer OpenQASM3, mid-circuit measurement, reset or control flow.

One submission makes one documented [v0.4 create-job request](https://docs.ionq.com/api-reference/v0.4/jobs/create-job). It does not call the SDK's retrying job creation method. A lost acknowledgement leaves the common intent uncertain, with its shots and jobs set aside. No replacement job is submitted. The public API has no qualified idempotency key or exact metadata/name lookup. Automatic reconciliation of an unknown job ID is therefore unavailable, and an empty/partial job listing is never treated as proof of rejection.

Without an acknowledged job ID, `Run.wait()` raises `RunFailed` with an uncertain recovery status. The original shots remain charged and no replacement job is submitted.

Use `nwqlib.prepare(plan, backend=backend, directory=...)` and `nwqlib.submit(prepared)` to obtain the same live Run. It can remain pending; `run.resume()` and `run.wait()` retrieve original jobs and advance the selected controller. The lower-level `submit_detached((handle,), run=run)` supports one multi-circuit job when its handles have equal requested shots. Native QPY is saved before original submission. Close the controller, then use `nwqlib.load_run(directory, backend=backend)` to reopen its same folder. A retrieval exception preserves that job for a later explicit refresh. Cancellation requests the known job's cancellation; only subsequent status establishes its outcome.

The readout requires a [raw histogram artifact](https://docs.ionq.com/api-reference/v0.4/schemas/results-formats). Both decimal-state histogram v1 and joint `output_all` histogram v2 are accepted. The decoder preserves unequal integer populations and applies the original measurement map. A v1 decimal key is read as an integer whose bit q is qubit q, the convention of qiskit-ionq's own decoder. A v2 binary key is read most significant first to give the same integer. That v2 reading is checked only against offline fixtures. Classical bit b takes the value of the qubit that the converter's measurement map assigns to b, and count keys put classical bit 0 rightmost. The decoder checks actual shots against both the histogram sum and the accepted shot count. Separate register marginals cannot establish a joint histogram and are rejected. Probability artifacts are never rounded, resampled, sharpened, or advertised as binomial counts or an exact readout. Counts from a fresh physical measurement do not establish IID samples, stationarity, or an error bound, and the selected method still owns its statistical assumptions.

For a histogram with `m` entries on `q` native qubits and `c` classical bits, decoding at `q,c<=64` checks `57*m + 8*min(m, 2**min(q,c))` bytes for live ndarray elements, including the returned index/count pair. The represented count-key bytes `m*(c+16)` are checked separately. Wider inputs use Python integers and bit-string keys within those represented-key bytes. Public count records count against the common stored-data limit. These per-decode checks do not bound Python object memory, transport buffers or the total memory of a batch.

Single-circuit and batch submissions require `debiasing=False`. A batch holds at most 5,000 circuits and 150,000 gates in total, the multi-circuit limits of the [create-job reference](https://docs.ionq.com/api-reference/v0.4/jobs/create-job). NWQLib counts one gate per entry of a circuit's IonQ gate list and applies the same 150,000-gate total to a single-circuit job, for which the reference gives no gate limit. Each input circuit receives an original submission/item name. Each returned child must have that name and the correct parent job. Its position in the returned list does not determine its measurement. The common journal preserves child IDs before publishing their individual observations. The selected raw artifact ID is kept with its child before download. Children are read once the parent job is no longer pending, and completed children can then be consumed while others remain pending. If a later status, download or decode fails, the common owner first commits the available child/artifact IDs and completed observations, then raises the original exception with its cause. These completed observations remain accessible by their original attempts even though refresh raised. Subsequent refreshes skip their already published artifacts and refuse to replace a known artifact ID. One batch remains one submitted job, with separate actual shot populations per child. Duplicate names, duplicate child IDs and replaced associations reject before artifact download.

Requested debiasing and ideal-simulator counts reject before submission. The ideal simulator ignores requested shots. Unexpected nested child jobs or debiasing variants reject before scientific publication. The [job schema](https://docs.ionq.com/api-reference/v0.4/jobs/get-job) provides variant IDs, shots and a nullable `qubit_map`, but does not define that map's direction or the coordinate convention of each variant artifact. Variant support must preserve these separate populations and establish those semantics; it cannot pool them by assumption. These are current support boundaries, not a claim that IonQ lacks those service facilities.

Offline qualification used Qiskit 2.5.2 and qiskit-ionq 1.1.1 with injected HTTP responses, including common finite-Pauli analysis and durable restore. No live QPU, account, queue, artifact availability or hardware accuracy was qualified. Preparation emits that limitation once per run. Submission and retrieval go only through the common execution interface above.

`max_input_bytes` limits serialized requests and optional QPY output. `max_response_bytes` limits the HTTP body bytes that the adapter reads from one response. The reader never holds more than one byte beyond it, and that extra byte is what reveals an oversized body, which is then rejected. Network buffering inside requests and urllib3, JSON object memory, provider compilation, runtime, RSS and billing remain unbounded by these fields. The request timeout is a connect/read timeout, not a total wall-clock deadline. Each refresh reads the known parent once and, when the parent is no longer pending, each outstanding child's status once. It downloads a completed child's selected raw artifact once, skipping already published child measurements. A failed download or decode may need an explicit later download of that same missing item. Children decoded before the failure are kept and not downloaded again. An interruption before durable publication remains distinct from that handled error path. No retrieval failure authorizes another submission. Run stored-data limits cover represented payload and saved output. They do not prove a bound on provider CPU, network latency or monetary limits.
